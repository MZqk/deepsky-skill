> 工具：`scripts/calibrate_star_damage_gate.py`（离线，非管线组件）
> 目标：给 `star_removal_profiles.RemovalProfile.damage_limit` 提供实测依据。
> **当前状态：不可定线**（`verdict.status = blocked`），原因见 §4。

## 0. 母版可测性筛查：raw sep == post sep

**先筛查再跑管线。** 跑一次管线约 8 分钟/份；但
`04_separation_reference.tif`（star_remove 的输入）上的
`subject_separation` 与**原始 XISF 母版逐位相同**（4 份样本实测）：

| 母版 | raw sep | post-DBE+color sep | Δ |
|---|---|---|---|
| NGC6888 | 1.3079 | 1.3079 | 0.000000 |
| M8 | 1.5702 | 1.5702 | 0.000000 |
| M17 | 1.0169 | 1.0169 | 0.000000 |
| NGC7000 | 1.0188 | 1.0188 | 0.000000 |

**机制**：`separation = p75 / p25` of `gaussian_filter(gray, sigma=8)`，
是**分位之比**；DBE 减掉的是大尺度背景梯度，对「平滑后 25 分位与 75
分位的比值」几乎无影响（两者同乘一个近似常数）。

⇒ 工具 `scripts/screen_calibration_corpus.py` **26 份母版 27 秒扫完**，
且每次运行都会用已有标定样本**重新验证这个等价性**（`--calib-root`）
—— 它是经验观察不是保证，失效时筛查会变成**系统性错误**且不报错。

⚠ **等价性只用于「排除」，入选仍须跑管线确认。** 它只在 4 份
`emission_nebula` 样本上验证过。

### 0.1 筛查必须同时报「类型来源」

不在本地星表（`fits_io.LOCAL_CELESTIAL_DB`）里的目标会走
`resolve_target_type` 的兜底猜测。实测 **C50（疏散星团）查不到**
⇒ 被猜成 `emission_nebula` ⇒ `is_star_poi_target` 返回 `False`
⇒ 管线的星团禁令**不触发** ⇒ 会在「星点即主体」的数据上跑完整去星链，
产出的 `damage` 语义不明。

⇒ 工具输出 `catalog.type_is_guessed`，这类目标**不作为首选**。

## 1. 为什么需要标定

`star_tools._star_removal_gate` 的接纳线 `damage_limit = 0.20` 是单一常数。
实测证明它在同一个 `target_type` 内就能差一个数量级：

| 母版 | target_type | 真实 StarNet2 产物的 `damage` | 门禁结论 |
|---|---|---|---|
| NGC6888 | emission_nebula | 0.2403 | advisory（接受） |
| M8 | emission_nebula | 0.3580 | advisory（接受） |
| M17 | emission_nebula | 0.0000（**不可测**，`separation=1.017 < 1.30`） | advisory（走 unavailable 分支） |

三份样本同为发射星云，`damage` 从 0 到 0.358；M17 干脆落在可测性判据之下。
**这直接否证了「一个常数适用于一档」**。

标定要回答的不是「damage 应该是多少」，而是**「在什么口径下、哪些数据上、
哪个量级」**。

## 2. 复现命令

```bash
# 1) 产出真实无星图（不能用回退副本，见 §3.1）
python3 scripts/pipeline.py \
  ~/SeeStar/Starun/SeestarS30Pro-NGC6888-60s720_LP.xisf /tmp/calib2/ngc6888/out.jpg \
  --target-type emission_nebula --target-name NGC6888 \
  --steps star_remove,stretch --use-starnet --keep-all \
  --low-memory-threshold-mpix 99.0 \
  --work-dir /tmp/calib2/ngc6888/work \
  --result-json /tmp/calib2/ngc6888/result.json \
  --override-params '{"deepsnr":"never"}'

# 2) 跑标定（V1-V4 + 门禁口径回放）
python3 scripts/calibrate_star_damage_gate.py \
  --corpus ngc6888 M17 M8 --calib-root /tmp/calib2 --replay \
  --json /tmp/dmg.json
```

**注意 `--low-memory-threshold-mpix 99.0` 必须是 CLI 参数**，不能写进
`--override-params`：它是 `run_pipeline()` 的**函数形参**，不在 `cfg` 里，
走 override 通道不会生效（实测 8.29MP 数据仍被自动低内存模式剥掉
`star_remove` 步骤）。默认 8.0 阈值下大图会跳过内置去星链。

## 3. 被实测否决的设计假设（12 条）

这一节是本文档最重要的部分。以下每一条都曾写在方案里、被实测数据推翻，
**记录在此以防重蹈**。

### 3.1 回退时把「恒等图」写进无星图产物路径

`_safe_star_removal_fallback()` 返回 `image.copy()`，而 `pipeline.py`
无条件把它落盘为 `04_starless_linear.tif`。逐字节 SHA-256 比对确认
9 组产物全部 `04_separation_reference.tif == 04_starless_linear.tif`。

后果：拿这对外文件做标定，`q ≡ 1`、构造全部落在死区，读数恒 0 ——
**标定静默失效且不报错**。

修复（v0.1.34）：回退时改落 `04_starless_fallback.tif`，并在
`result.json` 的 `artifact_meta` 标 `is_fallback_copy: true`。
标定器 `load_work_pair()` **只接受** `04_starless_linear.tif` /
`04_starless_external.tif`，回退副本直接进 `skipped` 并给出原因。

### 3.2 `nebula_mask_coverage > 0.60` 是死代码

主体掩膜由 `orig_smooth >= percentile(orig_smooth, 75)` 圈定 ——
**相对**分位，因此掩膜占比**数学上恒等于 0.25**。
实测 NGC6888 / M17 / M8 / M45 四份母版全部 `0.250000`。

⇒ 0.1.33 CHANGELOG 声称的「掩膜退化为全图」失败形态**不存在**。
处置：`DEPRECATED_FIELDS` 标弃用，退出可测性判定链，字段仍作观测量输出。
可测性回归 `subject_separation` **单判据**（实测 M17 正是被它拦下的）。

### 3.3 damage 闭式成立，但仅在不削顶区间

化简 `star_tools` 的实现可得：

```
q      = median(sl_smooth[M]) / median(orig_smooth[M])
damage = max(0, |1 − q| − 0.10)          # ±10% 死区，V 形双侧
```

实测（NGC6888 全分辨率，q=0.6597）7 档全部吻合到 **4.6e-05**。

**削顶边界**：构造的 `k` 太大时 `clip(sl*k, 0, 1)` 削顶，`q' ≠ k×`，
闭式失效。削顶阈值是**数据相关**的：NGC6888 需 `k > 2`，合成夹具
（`sl_smooth.max()=0.006`）需 `k > 166`。
⇒ 第一版测试写死 `k=4.0`，在合成数据上根本没削顶，「闭式失效」这条
性质测了个空。**必须按数据算 k，不能硬编码。**

### 3.4 标定口径必须是全分辨率，不能照抄保真度门禁的 1400px

`calibrate_fidelity_gates.py` 在 1400px 上标定（保真度门禁的调用点
`pipeline.py:2650` 显式过 `downsample_for_gates`）。**去星质量门禁的
调用点不过** —— `estimate_star_removal_quality` 直接吃 Phase 4 的
全分辨率线性图。

实测同一对 NGC6888 图，只换采样尺寸：

| max_side | shape | `subject_separation` | `measurable` | `damage` |
|---|---|---|---|---|
| 3840（全分辨率） | 3840×2160 | **1.3080** | True | **0.2403** |
| 2800 | 2800×1575 | 1.3040 | True | 0.2529 |
| 2000 | 2000×1125 | 1.2980 | **False** | 0.0000 |
| 1400 | 1400×788 | 1.2870 | **False** | 0.0000 |
| 768 | 768×432 | 1.2720 | False | 0.0000 |

**同一份数据、同一对图，1400px 口径得出「不可测、damage=0」，
全分辨率得出「轻度误伤、damage=0.24」——两个相反结论。**
且 NGC6888 的 separation 紧贴判据下限 1.30，跨口径必然翻转结论。

⇒ `CALIB_MAX_SIDE = None`。这是本工具最容易犯也最致命的错误：
跨口径定出的线拿到运行时会被判成另一个形态，而报告里看不出任何异常。

### 3.5 A 型亮度缩放**不是**「零混淆」构造

方案原假设：``sl·k`` 只改主体亮度，`residual` / `high_grad` 逐位不变
⇒ 可单独定 `damage_limit`。

实测**否证**：`high_grad_ratio` 会变（NGC6888 全分辨率 k=1.0→0.5：
0.0032 → 0.0008；合成夹具 0.0794 → 0.0000）。

机制：`high_grad_ratio` 的判据是 `grad_sl > max(grad_orig × 2, 6σ_sl)`，
其中 `6σ_sl` 是**绝对**噪声地板。`sl` 整体缩放时 `grad_sl` 与 `σ_sl`
同比缩放，但 `grad_orig` **不变** ⇒ 判据的相对关系被打破。

⇒ A 型判为 `confounded`，**没有任何构造是 `pure_damage`**。
这直接限制了本工具能交付什么：可以给「量级正确的候选线」，
**不能**给「经隔离验证的精确线」。`check_isolation()` 会在
`limitation` 字段自陈这一点。

### 3.6 E 型阴性对照的红线在数学上不可能成立（除非腐蚀）

`damage` 定义在 `gaussian_filter(gray, sigma=8)` 上，而**高斯核的支撑是
无限的**：掩膜外紧邻边界的一圈像素，其亮度会被卷进掩膜内。

实测（合成夹具，掩膜占比 0.25）掩膜外全损（f=1.0）时：

```
掩膜内中位比  0.6505 → 0.6373
damage       0.2495 → 0.2627     升幅 0.0132
```

⇒ 「掩膜外损伤 ⇒ damage ≡ 0」**不是门禁的缺陷，是构造的定义错误**。
正确做法：把待损伤区域**腐蚀 3σ = 24px**，使被改动像素到掩膜的距离
超过核支撑。实测腐蚀 24px 后 damage 逐位不变（Δ < 5e-5），
而 `residual` / `high_grad` 显著变化 —— 红线成立。

**配套的阈值坑**：红线阈值必须对齐 `nebula_damage_ratio` 的**舍入粒度**
（4 位小数 ⇒ 最小可分辨差 1e-4）。第一版取 1e-9，比最小可分辨差小 5 个
数量级，于是**任何舍入都判失败**：M8 实测掩膜外全损后 damage
0.3580 → 0.3581（升幅 1e-4，纯粹是 `round(0.35805)` 的进位）被报成
「E 型未通过，说明 damage 不是纯主体局部量」。

**这是假阴性，且指向错误的结论方向** —— 会让人怀疑门禁本身。
现取 `OUTSIDE_MASK_DAMAGE_EPS = 2e-4`（2 个舍入单位）：
容得下一次进位，容不下真实渗入（未腐蚀版本实测升幅 0.0132，大两个数量级）。

### 3.7 合成夹具的参数必须按实测反推

这是标定器**自身**的开发教训，与门禁无关但影响每一轮验证的可信度。

### 3.8 恢复中

> ⚠ **§3.8 ~ §3.12.3 的正文在 v0.1.39 编辑事故中丢失**，见文末 §7。
> 下列关键结论（均有代码/文档交叉印证）保留为要点，
> **完整推导待补**：

- **§3.10 V4 把原图当无星图** ⇒ 测不出数据抖动。`data_jitter()` 签名里
  没有 `starless`，把原图自己当无星图 ⇒ 配对变成 `(orig, orig×k)`，
  `q = 1/k` 是**代数后果**，与像素内容无关（实测 9 子窗 `q` 极差 0.000000）。
  该 bug 存活三个原因：V4 零测试覆盖；`summarize()` 根本不读 V4 字段；
  输出数字看起来合理（0.0 / 0.3 都像真实读数）。
  教训：**「报告里有个看起来合理的数字」不等于「它在测那件事」**。
- 同节并发缺陷二：子窗用同一个 `frac` 算 y0 与 x0 ⇒ 全部沿**一条对角线**
  排列（实测 n=5 距中心 (-615,-346)→(+614,+345)），**四个角一个都采不到**。
- 同节并发缺陷三：0/0.3 双峰不是噪声而是**可测性翻转**。`separation` 在
  1.25~1.35 横跨下限 1.30 ⇒ 部分子窗 `raw_change` 被强制 0.0。
  修法（v0.1.35）：配对接真实 `starless` + 2D 网格 + 按 `measurable` 分层。
  实测 NGC6888 `q_spread` 从 0.000000 变成 0.0635。
- **§3.11 A 型的单调方向与直觉相反**：实测（NGC6888，q=0.6597）k 从
  1.00 → 0.50，damage 从 0.2403 → 0.5701 **单调升**。方向是「k 越小 =
  主体越暗 = 误伤越大」。第一版标成 `monotonic_decrease` 是**标签错**，
  不是构造错。
- **§3.12 V5 改相对倍率网格**（`α = 1 + β`，`β ∈ (0, 0.1, 0.25, 0.5, 1, 2, 4)`）
  仍不可定线：健康组 ceiling 0.5371 > 劣化组 floor 0.0789 ⇒ 区间为空。
  根因是结构性的：健康基线跨 **10 倍**（0.0357~0.3580），而「最轻劣化」
  相对各自健康态只抬高约 **0.033**。
  **⚠ 本节的根因已在 §6 找到**：`damage` 把被移走的星光算成了误伤。

## 4. 当前标定结论

**v0.1.36 更新**：样本从 3 份补到 **8 份**（新增 NGC2237 / IC434-S50 /
C50-S50 / IC434-S30），可测样本 **5 份**。

```
verdict.status = blocked
blocking_reasons:
  - 误伤指标不可测（separation < 下限）：M17, NGC7000, IC434-S30
  - 数据抖动未测（可测子窗不足 3 个）：M17, NGC7000
```

**两条阻塞都只指向那 3 份不可测样本**，不再指向「抖动过大」——
后者已由 v0.1.35 修正为「未知」，现在**已知且可接受**：
6 份样本的 `measurable.spread` 全部落在档内 damage 全距（0.3223）之内，
最大者 IC434-S50 占 31%，`jitter_exceeds_damage_range` 为空。

### 4.2 尚存的阻塞

1. **三份样本母版级不可测**：M17（sep 1.017）、NGC7000（1.019）、
   IC434-S30（1.268）均 < 1.30。M17 与 NGC7000 的 9 个子窗**无一可测**
   （`unmeasurable_fraction = 1.0`）；IC434-S30 母版级不可测但
   **子窗层仍可测 4 个**（`measured`），所以它只触发「不可测」阻塞、
   不触发「抖动未测」阻塞。
   这三条不是失败，是这些数据落在可测性判据之下。
2. **NGC6888 与 IC434-S30 仅 44% 区域可测**（各 5/9 子窗不可测）
   ⇒ `damage` 阈值在这两份数据上**代表性有限**。
3. **D 型（空间位移）单调性未通过**。`high_grad` 强增导致饱和形态
   与预期不符；它本就不能单独定线（几何错位档），优先级最低。

> **v0.1.35 的更正仍然有效**：曾把「NGC6888 V4 spread=0.30」列为最硬的
> 阻塞。该数字来自 `[0,0,0,0,0.3]` 的**双峰** —— 0 来自不可测子窗
> （`raw_change` 被强制 0），0.3 来自可测子窗；它衡量的是
> 「可测子窗占比」，不是读数稳定性。**数据抖动在 v0.1.34 中
> 从未被测量过** —— 不是「很大」，是「未知」。
>
> v0.1.36 补样本后，抖动**已知**：6 份样本的组内 spread 为档内全距的
  31% 以内，`jitter_exceeds_damage_range` 为空。

### 4.3 恢复条件

标定可恢复当且仅当：**健康组内部极差 ≪ 健康到劣化的间隔**。
按 v0.1.37 的数据这需要组内极差从 0.3223 降到 ~0.027 以下（12 倍压缩）。
可能路径：补足可测母版（当前库存已见底，需新数据源）、
或改用对全局缩放可见的**局部**判据（尺度不变类判据已实测对A 型盲视）。

> **v0.1.39 已走第二条路**，见 §6：判据改为扣除星层通量后，
健康组极差从 0.3223 降到 0.0883（按新死区 0.02 计，Rec.709 口径）。

7 份真实 StarNet2 产物（跨机型/跨分辨率/跨目标类型）。

### 6.2 判据：主体基准扣除同掩膜内的星层通量

### 6.4 踩坑记录（新增 2 条，与 §3 同等重要）

**(a) 星层不能由 `orig - starless` 派生。**
派生量与被测量共用同一个减法 ⇒ 注入的损伤会**同时**被算进「星层」，
分母被补偿掉，读数变成**非单调**。实测 M8：

```
beta  0.00    0.05    0.10    0.20    0.30
读数  0.0942  0.0945  0.0948  0.0917  0.0773    <- 越损伤越小
```

星层必须是**独立观测量**（去星时的产物）。实现上：StarNet 路径用
内部分解出的 `stars`，形态学路径用**检测掩膜 × 原图**（掩膜是去星前的
独立决策，不含修复残差）。缺少星层时该读数标记为 `available=False`，
**不产出 0**（0 会被读成「没误伤」）。

**(b) 劣化构造必须与被测样本的 `q` 所在侧同向。**
`damage` 是 V 形双侧量（`q=0.70` 与 `q=1.30` 读数相同）。健康态实测
**5 份里 3 份 `q_sf > 1.0`**（NGC6888 1.006、C50 1.031、NGC2237-DW 1.109）。
若一律「压暗主体」，这 3 份会被推向 `q=1.0`，读数**先降后升**：

```
NGC2237-DW  beta 0.00 -> 0.10 -> 0.20 -> 0.30
          0.0894    0.0292  0.0000  0.0696    <- 中间塌到 0
```

这不是判据缺陷，是构造假设错误。正确做法：按各自健康 `q_sf` 相对 1.0
选择方向，度量「离健康态的距离」。

**(c) 离线标定脚本里灰度化会静默作废整个读数。**
劣化构造需要灰度图，但 `stars` 若保持 3 通道，
`estimate_star_removal_quality` 的形状守卫会直接拒绝 ⇒
`star_flux_metric_available=False`、读数恒 0，**且不报错**。

实测：NGC2237-S30Pro 在「2D 灰度原图 + 3 通道星层」下全 β 读 0，
看起来像「该样本对劣化不敏感」，实际是夹具自身废了。

⇒ 灰度化必须对 `original` / `starless` / `stars` **三者同时**做，
且用 `gray()` 而非 `.mean(2)`：线上走 Rec.709，通道均值会有 ±0.02 偏差。

**与 §3.10 同源的错误模式**：输出是一个看起来合理的数字（0.0），
而它压根没在测那件事。判据失效与夹具失效都会产生「恒定读数」，
**不能用读数合理性来判断成败**。

#### 6.7.3 可行方向：相对判据（每图基线）

若以**每张图自己的健康值**为基线，度量变化量 `delta = |1-q|_now − |1-q|_healthy`：

| β | delta 范围 | 全样本 > 0 |
|---|---|---|
| 0.15 | 0.0560 – 0.0876 | ✓ |
| 0.20 | 0.0748 – 0.1202 | ✓ |
| 0.22 | 0.0816 – 0.1331 | ✓ |
| 0.30 | 0.1119 – 0.1851 | ✓ |

**分离干净，且下界在 β=0.15 就为正。** 代价：需要同一张图的健康基线，
即门禁只能在**第二次**处理同一图时触发（首次运行无基线可比）。

这是与当前架构的**结构性冲突**，不是参数问题 ——
`_star_removal_gate` 是单次调用的纯函数。落实需要：
在 `result.json` 持久化每图基线，并让后续运行读取它。**尚未实现。**

|---|---|

| `eff_n` | +0.0482 |

⇒ `star_free_snr` **只作为观测量**输出，**任何判定都不得引用**。

## 8. 相对判据（v0.1.44）：唯一已验证可行的路线

### 8.1 为什么必须是相对判据

§6.7 用 6 份样本证明：**绝对读数在原理上不可分** —— 健康组自身的 spread
就有 0.0959，与「最轻劣化」造成的位移同量级。死区怎么调都无效（§6.7.1）。

先排除了一条捷径：**单次运行内导出基线是行不通的**。实测三个候选指标
全部失败：

| 候选 | 思路 | 结果 |
|---|---|---|
| `hi_mad` | 差值场中位数/MAD，判结构 vs 噪声 | ❌ 最高损伤样本值**最低** |
| `coherence` | `corr(field, gaussian(field, σ=24))` | ❌ 健康带 0.678~0.808，与所有劣化档**重叠** |
| noise fraction | 差值落在 1σ 内的比例 | ❌ 恒为 0 |

根因：**健康态本身就不是「无变化」状态**。StarNet2 会让延展发射暗 1~11%，
而这些暗化同样是**空间连贯**的 —— 在图像上与轻微误伤是同一类现象。
单次运行的任何形态学指标都无法把二者分开。

> 另有一层等价性：单次运行内门禁看到的是 `(orig, starless, stars)`，而
> `q = median(sl[M]) / (median(orig[M]) − median(stars[M]))` **已经**以
> orig 为基准。「相对自身原图的偏离」在数学上就等于现有判据，不产生新信息。

### 8.2 判据定义

```
baseline   = |1 − q_sf|                       # 本次运行的值，本身就是基线
delta      = max(0, baseline_now − baseline_ref)   # 相对上次多坏了多少
```

健康态 delta 按构造为 0；劣化恒为正。

**关键性质：delta 不分 target_type。** 它度量的是「比上次多坏多少」，
量纲与目标类型无关 —— 这正是绝对路线做不到的。

### 8.3 实测分离（Rec.709 口径，与线上 `estimate_star_removal_quality` 逐位一致）

健康基线（**8 份**真实 StarNet2 产物；v0.1.44 扩充 M8 与 C50-S30）：

| 样本 | baseline |
|---|---|
| M31-S30 | 0.0124 |
| NGC6888 | 0.0175 |
| C50-S50 | 0.0392 |
| NGC2237-DW | 0.0606 |
| NGC2237-S30Pro | 0.0651 |
| C50-S30 | 0.0843 |
| IC434-S50 | 0.1083 |
| **健康带 spread** | **0.0959** ← 绝对路线的死结 |

劣化构造沿各自健康 `q_sf` 的**反方向**注入（避免 V 形双侧量在 q=1 附近塌陷，
见 §6.4(b)）：

| β | delta 范围（8 份） | 全部 >0 |
|---|---|---|
| **0.02** | 0.0071 – 0.0137 | ✓ |
| 0.03 | 0.0110 – 0.0206 | ✓ |
| 0.05 | 0.0183 – 0.0342 | ✓ |
| 0.08 | 0.0292 – 0.0543 | ✓ |
| 0.10 | 0.0366 – 0.0677 | ✓ |
| 0.15 | 0.0560 – 0.1015 | ✓ |
| 0.20 | 0.0748 – 0.1356 | ✓ |
| 0.30 | 0.1119 – 0.2049 | ✓ |
| 0.45 | 0.1918 – 0.3060 | ✓ |

**分离从 β=0.02 就成立**，故 `(0, 0.0071)` 内任何常数都能分开健康与劣化。
对比绝对路线：β=0.30 才勉强分离（0.1119 vs 0.1083，余量 1.03×）。

> ⚠ 以上 delta 范围是**合成劣化**下的读数，不是「真实误伤」的上界。
> 阈值定线据此给出，但仍属工程标定（见 §8.6）。

### 8.4 门禁的三级语义

```
有 baseline + 有对照  → 用 delta（相对判据）
有 baseline + 无对照  → 只出基线，门禁记 advisory（首次运行）
无 baseline           → 沿用绝对判据（行为逐位不变）
```

第三级能静默回退，是因为绝对读数是**每次都算**的既有量；且
`damage_limit` 本身已标定为 `None`（走 uncalibrated），不会误判。
前两级**不静默回退** —— 拿绝对阈值判 delta 会得出无意义结论。

### 8.5 用法

```bash
# 第一次：产出基线（写进 result.json 的 star_removal.star_flux_baseline）
python3 scripts/pipeline.py input.fits out.jpg --use-starnet \
  --result-json r1.json --override-params '{"star_flux_normalize":true}'

# 第二次：读回基线，启用相对判据
python3 scripts/pipeline.py input.fits out2.jpg --use-starnet \
  --star-removal-baseline r1.json --result-json r2.json \
  --override-params '{"star_flux_normalize":true}'
```

**来源校验**：读回时比对 `input` 的 realpath 与 `star_removal_profile.target_type`，
任一不符即拒绝并打印原因。换图沿用旧基线会得出「这次更健康」的荒谬结论。

> ⚠ **必须开 `star_flux_normalize`**。它此前**没有任何 CLI 入口** ——
> `pipeline.py` 从不 import `star_removal_profiles`，这些门禁档字段只能
> 改代码表。v0.1.44 补上 `_star_removal_profile_for()`，逐字段走
> `apply_profile` 故仍受单向棘轮约束。

### 8.6 当前状态：机制已通，**阈值已定（工程标定）**

```
damage_delta_limit = 0.005    # = beta=0.02 分离上界(0.0071) 的 0.70x
verdict.status = usable_with_caveats
```

**定线依据**：9 档 β（0.02~0.45）× 8 份真实 StarNet2 产物。
每一档的 delta 下界都 > 0.005，即 0.005 可检出 β>=0.02 的劣化。
取值刻意取上界的 **0.70x** 而非贴边 —— §6.7 警告过「刚好可分等于没标定」。

**仍存在的限制**：

- ⚠ **delta 来自合成劣化构造，缺真实误伤样本的上界**。该值属工程标定，
  样本积累后应复核。若真实误伤的 delta 分布比合成构造更宽，需上调。
- **三档零样本**：`planetary_nebula` / `dark_nebula` / `reflection_nebula`
  在本库**没有任何母版** —— 星表收录 10 个目标（M1/M27/M57/M97、
  B142/B33/LDN1622、IC2118/M78/NGC7023），本地一份都没有。
  这是**数据限制**，不是标定缺口：需要先拿到这些目标的原片。
  ⇒ 相对判据的一个附带优势：**阈值不分档**，所以这三档补样本后
  原则上**不需要重新定线**，只需验证 delta 分布落在同一区间。
- `galaxy` 档目前只有 M31-S30 一份（唯一 sep>1.30 的星系母版），
  但由于阈值不分档，同样不阻塞。

**下一步建议**：拿到 M1/M57 等任意 PN 母版后跑一次，验证 delta 落在
(0.005, 0.0071) 之外即可确认阈值可跨类型复用。
