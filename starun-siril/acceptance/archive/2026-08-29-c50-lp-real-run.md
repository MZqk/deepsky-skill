## 8. 2026-08-30 勘误：SSF 来源、通道状态与当前合同

本节只校正报告解释，不改写上述历史命令、session 或哈希。

1. 本轮对冻结手册实际执行的是一次 `--verify-bundle`，没有执行 `--command` 或 `--read`。两份 SSF 是
   Agent 逐字参数化 `input-inspect.md` 与 `delivery-render.md` 的完整骨架，并通过
   `command-policy.json` 校验；因此“读取手册”只证明 Bundle/依赖知识基座完整，不能表述为“逐命令查询过
   Siril 原文”。按当前按需规则，这两份脚本应记录 `manual_lookup.status=not_needed`、具体原因和空 evidence；
   若使用 neutral/SPCC、modified-SHO、asinh 等未展开变体，则必须另做 command/read 查询。
   当前 runtime 已改为由 `init` 自动验证并冻结 Bundle，新的执行任务不应在 `init` 前再手动重复验证；
   显式 `--verify-bundle` 留给纯知识查询、解包/发布检查或损坏诊断。
2. 初始化命令中的 `--channel-mode broadband` 缺少足够的用户、采集或文件内来源证据，是过度声明。当前
   判断应为 channel unknown；不能从文件名、Seestar 型号或青绿色显示推断 broadband/dualband/narrowband。
   原 session 是 immutable 历史证据，未就地修改；任何当前合同复验都应新建 session 并传
   `--channel-mode unknown`。
3. 该历史 session 生成时尚未要求 `scripts/<run-id>.provenance.json`，所以表中两份 `.ssf` 均没有当前
   `deep-sky-siril.ssf-provenance.v1` sidecar，`session.json` 也没有当前 `init` 自动写入的冻结 knowledge
   binding。它们可继续证明当时的 Siril 执行、像素审查和失败关闭结果，但不得宣称已通过当前 provenance/
   knowledge 门，也不能直接在当前 runtime 下作为合规 replay。新复验必须新建 session，并为每份
   `run`/`--validate-only` SSF 创建同 stem sidecar，绑定脚本、唯一 primary protocol reference、policy、
   实际 manual evidence 和参数理由。
4. unknown 路由的准确边界是 `input.inspect` 产生并审查 display-only 父源，随后最多执行一次
   `delivery.render`；两者之间不得插入科学处理。最高 `partial_success` 只是状态上限，不豁免最终五门。

   `outputs/final.jpg` 的结论保持不变。

   Schema、sidecar 门和文档闭包后会变化，不能作为当前 release 的验证结果。当前发布仍保持
   `publishable=false`，且本勘误没有创建标签、上传或发布。
