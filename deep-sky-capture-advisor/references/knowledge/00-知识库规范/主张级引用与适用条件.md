# 主张级引用与适用条件

**摘要**：页面级 `sources` 只能说明“写作时参考了什么”，不能证明一条具体参数、软件行为或安全建议为何适用于当前读者。凡是会改变采购、运行或处理决定的结论，都要把来源、版本、适用条件、验收方式与不确定性放在读者能就近检查的位置。[^maintenance-policy]

## 何时必须使用

以下内容必须使用正文 `[^source-id]` 就近引用，并写明改变结论的条件：

- 数值、公式、单位换算、阈值、参数范围或测试结果；
- 具体型号、驱动、固件、软件菜单、支持范围与版本行为；
- 供电、机械运动、天气、无人值守或数据不可逆操作的停止条件；
- 可被误读为通用规则的案例参数、用户经验或截图结论。

纯粹的目录导航、术语别名和本地阅读建议可以不逐句引用，但不得借此夹带上述外部事实。页面级 `sources`、`stale_after` 与 `review` 仍是最低要求，不被主张级引用替代。[^maintenance-policy]

## `applies_to`：先写条件，再写建议

在 frontmatter 中使用结构化 `applies_to` 描述页面范围；新页面至少按实际情况填写系统/软件、观测条件和不适用范围。字段可以按主题增加，但值必须是读者能检查的具体条件，而不是“通用”“视情况而定”。

```yaml
applies_to:
  系统: ["德式赤道仪", "带主相机与导星设备的深空长曝光系统"]
  软件与版本: ["N.I.N.A：以正文注明的手册访问日期为准"]
  观测条件: ["已完成白天运动包络与停泊测试"]
  不适用: ["没有安全停泊能力的无人值守系统", "经纬仪的长曝光翻转流程"]
```

正文中的每个关键主张再用一句“适用条件”收窄范围。例如，“翻转后重新居中”只适用于已经验证赤道仪时间/地点、限位与板解链路的相应平台；它不是任何赤道仪的默认安全行为。[^p0-source-record]

## 最小主张卡

一条高影响结论至少应能还原以下信息。它可以写成紧随段落的表格、列表或结构化数据；不要求把同一信息复制到多个页面。

| 字段 | 要求 |
|---|---|
| `claim_id` | 页面内稳定、可复用的标识，例如 `automation.meridian-flip.recenter`；改写措辞不改变 ID。 |
| 结论 | 可被证伪的短句；不要把多个条件、动作和结果粘成一句。 |
| `applies_to` | 设备/光路、软件与版本、地点/天空、目标或数据状态中的必要前提。 |
| 证据 | `[^source-id]`，并在来源项记录访问日期；PDF 或版本文档尽量保留页码、章节或发行版本。 |
| 验收产物 | 读者可保留的日志、测试帧、截图、计算输入、拒绝图或现场检查记录。 |
| 失效与冲突 | 何时复核、何种输入会使结论失效，以及存在分歧时显示哪些候选说法。 |

推荐将 `claim_id` 写入紧邻结论的 HTML 注释或维护表，而不是用它代替人类可读的标题。构建或问答系统若抽取该主张，必须同时带回适用条件、来源和审核状态。[^p0-source-record]

## 来源、版本与权利

每个 `sources` 条目优先补齐下列字段；`rights` 的 `unknown` 表示只保留必要书目信息与外链，不表示已获转载、嵌入或训练许可。[^maintenance-policy]

```yaml
sources:
  - id: src-example
    resource: "https://example.org/manual"
    title: "厂商手册标题"
    accessed_at: "2026-08-13"
    rights: unknown
    usage: link-only
    version: "若来源明确发布版本，则记录于此或正文"
```

来源卡的访问日期不是“事实仍然正确”的证明。软件、驱动、固件、价格和在线服务出现新版本时，应检查与其关联的主张；静态原理仍按页面 `stale_after` 复核。[^p0-source-record]

## 冲突、不确定与人工审核

1. 不同设备、版本或经验给出不同结果时，先检查是否只是 `applies_to` 不同；不要把它们平均成一个“通用阈值”。
2. 条件相同但证据冲突时，保留各自来源、版本和冲突说明，并将主张标为待人工裁决。
3. 缺少型号、版本、单位、日志或现场条件时，输出待补充字段与最小验证步骤，不猜测结论。
4. `stable` 只说明页面结构完整；只有具名真人逐项核对后才可写入 `verified: { by: human:<id> }`。[^maintenance-policy]

## 作者与审核者检查清单

- [ ] 结论是否可定位到同页 `[^source-id]`，且 `sources[].id` 存在？
- [ ] 是否记录了会改变结论的设备、版本、天空/数据或操作前提？
- [ ] 是否区分了“筛查指标”“建议起点”和“可停止/拒绝的条件”？
- [ ] 是否保留了读者可复核的测试产物和恢复路径？
- [ ] 是否声明了来源访问日期、权利状态和版本触发复核？
- [ ] 是否没有把机器检查、社区经验或案例参数标为人工已核验？

## 权威问答口径

- 本页可承担的回答范围：包含外部事实或会影响用户决定的正式 Wiki 页面及其问答派生内容；成立条件：主张、来源、适用条件、版本、失效边界和审核范围可逐项追溯。
- 遇到以下情况必须拒绝确定结论或转入专项页/实测：纯目录页；无外部事实的本地导航说明。
- 具体数值、兼容性、软件行为或安全结论只使用正文就近绑定的来源，并同时受 `stale_after` 与人工 `verified.scope` 限制。
