# 数据管理、命名、备份与可复现归档

**摘要**：深空数据的价值不止在最终成片。原始 Lights、校准帧、FITS 头部、会话清单、处理参数、拒绝帧名单和独立备份共同决定它能否被重新校准、重新叠加和可靠恢复。原则是：原始数据不覆盖；每次拍摄可解释；每次处理可复跑；唯一副本不算备份。

## 背景 / 适用场景

适用于单夜到多夜、多滤镜、远程台或团队协作的数据。本文不要求某一软件或云盘，也不强制单一命名法；重点是让每个项目能回答“这是什么、怎么拍、用什么校准、怎样处理、是否已备份”。

## 项目目录：把原始、主帧、过程和导出分开

以下结构可按软件调整，但不要把原始数据与可随时重建的中间文件混在一个目录里。

```text
YYYY-MM-DD_目标名/
  00-session/          # 会话 manifest、计划、设备/软件版本、天气与异常记录
  01-raw/
    lights/             # 不覆盖的原始亮场，按日期/滤镜/相机状态再分组
    calibration/        # darks、flats、biases、darkflats 等原始校准帧
  02-masters/           # 可由原始校准帧重建的主帧，保留生成条件
  03-process/           # 校准、注册、整合、中间图、脚本与项目文件
  04-exports/           # 发布版 JPEG/TIFF、说明文字；不替代母版
  05-logs/              # 采集、导星、处理、校验和与异常日志
```

Siril 的官方预处理脚本也要求按 `lights`、`darks`、`flats`、`biases` 等目录组织输入；这说明稳定目录结构能降低自动化与重处理的歧义。[Siril Script Files](https://siril.readthedocs.io/en/latest/scripts/Script-files.html)

## 命名与分组：以可还原状态为目标

采集软件自动命名通常优先于手工改名。若需自定义名称，至少能区分日期/UTC、目标、帧类型、滤镜、曝光、相机状态和序号，例如：

```text
20260730_221530_UTC_M42_Light_Ha_300s_G100_-10C_001.fit
```

命名不是唯一真相：相机的读出模式、offset、binning/ROI、传感器姿态、镜头/滤镜状态等信息未必都适合塞进文件名，应写入会话 manifest，并保留原始 FITS 头部。

## 会话 manifest：最小应记录什么

每次拍摄新建一份 `session.yaml`、Markdown 或电子表格，至少保存：

| 类别 | 最小字段 |
|---|---|
| 身份与时间 | 项目名、日期、UTC 起止、目标、拍摄地点/远程台标识；公开前单独处理精确位置隐私。 |
| 光学与机械 | 镜筒/改正镜、焦距、相机、滤镜、OAG/导星、光路顺序、相机旋转角和关键间距。 |
| 相机状态 | 温度设定与实际温度、增益、offset、读出模式、binning/ROI、曝光、帧类型。 |
| 采集与质量 | 每组计划/实际帧数、异常、导星/天气摘要、是否更换滤镜或重新对焦。 |
| 校准对应 | 哪组 Dark 对应哪组 Light、Dark Flat 对应哪组 Flat、Bias 的相机状态。 |
| 处理可复现性 | 软件与版本、脚本/项目文件、关键参数、被拒绝帧清单、主帧来源、导出设置。 |
| 完整性与备份 | 文件数、校验清单位置、每个独立副本的存储位置和最后一次恢复验证日期。 |

FITS 是科学数据格式，文件头可保存采集元数据。Siril 文档列出的常见字段包括 `DATE-OBS`、`IMAGETYP`、`EXPTIME`、`FILTER`、`TELESCOP`、`INSTRUME`、焦距、温度、增益、offset 与 binning；不同采集软件写入的字段并不完全一致，缺失字段应补进 manifest，而不是事后猜测。[Siril FITS 文档](https://siril.readthedocs.io/en/latest/file-formats/FITS.html)

## 采集后先做完整性检查

1. **确认落盘完成**：检查每组计划帧数、文件大小、可打开性和随机抽检的 FITS 头部；文件数量相同不等于参数相同。
2. **保留原始文件**：校准、去拜耳、裁切或格式转换都在副本或过程目录进行；不覆盖 `01-raw/` 的原始数据。
3. **生成传输记录**：跨硬盘、网络或远程台下载后，为文件/目录生成校验清单（如 SHA-256），在目标副本重新核验。校验和验证传输完整性，不代替备份。
4. **查看校准组边界**：按滤镜、曝光、温度、增益、offset、读出模式、binning/ROI 分组；不把名称相近的文件直接合并。

FITS 标准是天文数据的正式参考规范；其中也定义了可用于数据完整性核验的约定。具体软件是否保留内嵌 `CHECKSUM`/`DATASUM` 字段各不相同，因此项目级校验清单仍应单独保存。[NASA/IAU FITS 标准](https://fits.gsfc.nasa.gov/fits_standard.html)

## 备份与恢复：用独立副本防止单点故障

- 在采集电脑以外保存至少一个独立副本；有条件时再保留异地或可信云端副本。
- 不把同步文件夹、RAID、移动硬盘或回收站单独称为“备份”：它们分别可能遭遇同步删除、阵列故障、遗失或清空。
- 备份目录应包含原始数据、manifest、校验清单、处理脚本/项目文件和最终母版；只备份 JPEG 无法重建处理流程。
- 定期随机选择一个项目，在另一块介质或另一台电脑上校验并打开原始文件、读取 manifest、定位处理配方；能恢复才算验证过。

## 处理配方与版本留存

处理不是只有最后一张图。每次整合至少保存：

- 输入分组与校准主帧的路径/版本；
- 质量筛选、加权、拒绝算法和 rejection map；
- 背景、色彩、拉伸、降噪等关键步骤的项目文件、脚本或截图；
- 软件、脚本、插件和相机驱动版本；
- 可继续编辑的线性母版与发布版的导出参数。

Siril 建议自定义脚本放在用户自定义目录，而不是会随软件更新覆盖的内置脚本目录；把项目使用的脚本副本保存到 `03-process/`，可避免日后无法复跑。[Siril Script Files](https://siril.readthedocs.io/en/latest/scripts/Script-files.html)

## 发布前的最小检查

- [ ] 已从原始数据重新核对帧数、分组和校准匹配关系。
- [ ] 原始数据、manifest、处理配方和校验清单有独立副本。
- [ ] 导出文件与可编辑母版分开保存；发布版不覆盖线性或高位深母版。
- [ ] 分享原始 FITS、日志或截图前，检查是否含精确位置、设备序列号、账户名或网络信息。
- [ ] 能在不依赖记忆的情况下说明：使用哪组数据、哪套软件、哪些参数得到当前结果。

## 权威问答口径

- FITS 头字段、数据类型和扩展结构应遵循 FITS 标准；软件能够打开文件不等于元数据完整或像素值未被改变。[^src-fits-standard][^src-siril-fits]
- 可复现归档至少要保留原始帧、校准帧、处理参数/脚本、软件版本和输出谱系；脚本语法与执行边界以当前 Siril 官方文档为准。[^src-siril-scripts]
