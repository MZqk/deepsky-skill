# 采集参数试拍与总积分

**摘要**：增益、offset/黑电平和单张曝光不是可从别人的设备抄来的固定组合。应先固定相机模式、光路、滤镜和目标，再用实际天空背景、亮星饱和、主相机星点、导星/抖动开销和有效帧率比较候选设置。最终目标是积累可用积分，而不是追求某个单张秒数。[^sharpcap-smart-histogram]

## 先建立可比较的输入

每次试拍前把会改变结果的条件写入会话 manifest；相机的增益刻度、offset、读出模式与位深都必须按具体型号和驱动解释。[^data-manifest]

| 组别 | 必须固定或记录的条件 | 为什么 |
|---|---|---|
| 相机 | 型号、驱动、读出模式、位深、binning/ROI、增益/ISO、offset/黑电平、设定与实际温度。 | 同一“gain 100”在不同相机/模式下没有可比性。 |
| 光路 | 主镜/改正镜、焦距/焦比、相机旋转、滤镜、对焦状态。 | 视场、星点、暗角和背景响应会改变。 |
| 天空与目标 | 目标高度、月亮几何、透明度、局部光源和目标/构图。 | 背景会随高度、月亮、透明度和滤镜变化。[^sharpcap-smart-histogram] |
| 跟踪与开销 | 极轴/导星状态、风、单帧下载、抖动和稳定等待。 | 更长或更短的单张会改变拒片风险、可拍帧数与存储。 |

不要把“传感器规格曲线”与“当夜背景测量”混为一谈。SharpCap 的 Sensor Analysis 可测量相机增益、读噪和动态范围；Smart Histogram 再把传感器分析与目标位置的天空背景结合，用于比较不同增益/曝光组合的最终堆栈表现。[^sharpcap-sensor-analysis] [^sharpcap-smart-histogram]

## 用候选组做小样本试拍

1. **选择目的**：先决定是保护明亮核心/星色、降低读噪影响、减少拖线/饱和，还是控制文件与下载开销；一个候选组不必同时最优。
2. **只改变少数变量**：保持目标、滤镜、焦点和天空时段尽量接近，比较两到三个合理的“读出模式 + 增益/ISO + offset + 单张曝光”组合；不要同时更换相机、滤镜和算法。
3. **取得同等测试序列**：每个候选组拍足以观察背景、亮星、主相机星点、导星稳定和下载/抖动行为的连续原始帧；保留所有帧，不先覆盖或裁切。
4. **先看原始帧，再看推荐值**：检查背景位置、亮星饱和、星点、固定图样、轨迹与拖线。计算或软件建议只用来缩小候选范围，不能跳过主相机测试。[^sharpcap-smart-histogram]
5. **决定生产参数**：选择在当前约束下有较高有效帧率、可正确校准且动态范围/文件开销可接受的一组；把它写成“此系统、此滤镜、此天空下的起点”，而不是全局模板。

## 评价候选组，而不是只看直方图

| 观察项 | 记录方式 | 只能说明什么 |
|---|---|---|
| 背景与饱和 | 每组查看原始直方图、亮星和核心区域；注明软件单位与是否裁去边角。 | 判断背景是否已离开读噪主导区、亮部是否受损；不能单独代表最终信噪比。 |
| 传感器模式 | 厂商规格或分析结果中的增益、读噪、满阱/动态范围、位深。 | 解释候选组的取舍；不能替代目标和天空实测。 |
| 主相机星点 | 连续原始帧的 HFR/FWHM、偏心率或目视星场，连同焦距和采样记录。 | 发现失焦、拖线、风或视宁度变化；不同系统的绝对值不可横比。 |
| 有效帧率 | 计划帧数、保存帧数、拒绝原因、下载/抖动/稳定等待和存储占用。 | 说明同一可用时长实际积累了多少可用数据。 |
| 可校准性 | 是否有匹配的 Dark、Flat、Bias/Dark Flat，及校准后的残差。 | 防止只因单帧好看而选到难以稳定校准的参数。[^calibration-frames] |

Smart Histogram 的目标是比较固定总拍摄时间内的最终堆栈质量，不是让每一张子曝光都“看起来最好”；它仍要求按相机、滤镜、天空背景与最小/最大曝光约束解释结果。[^sharpcap-smart-histogram]

## 总积分与抖动

把总积分写为合格亮场曝光之和：`T_valid = Σ(每张合格 Light 的曝光时间)`。计划时还要另列下载、抖动、稳定等待、重新对焦、翻转和拒片造成的时间；它们不应伪装成有效信号。

- **优先总有效积分**：当候选单张都已满足当前读噪、动态范围和跟踪约束时，更多合格帧通常比盲目拉长单张更可解释。
- **抖动是成本也是收益**：它会占用导星稳定与下载间隔，但可以让固定图样在叠加中不总落在同一像素。抖动间隔要记录为序列条件，不能只写“已开启”。
- **校准关系不可省略**：改变曝光、增益/ISO、offset、读出模式、温度、binning/ROI 或滤镜状态后，重新检查对应校准帧是否仍匹配。[^calibration-frames]

## 参数试拍记录卡

将下面的卡与原始帧、导星日志和处理配方一起保存；缺少任何关键输入时，结论应标记为待比较，而不是直接复制到下一夜。[^data-manifest]

```text
项目/日期/地点：
目标/高度/月亮与透明度：
主镜/焦距/相机/滤镜/旋转：
相机模式/位深/binning/ROI/温度：

候选 A：gain/ISO ___；offset/黑电平 ___；曝光 ___；抖动 ___
候选 B：gain/ISO ___；offset/黑电平 ___；曝光 ___；抖动 ___
每组原始帧位置与数量：
背景与亮星检查：
主相机星点与导星/风摘要：
下载、抖动、稳定等待与存储：
校准帧匹配与残差检查：
本夜采用的起点、理由与下次要改变的单一变量：
```

## 何时停止，而不是继续优化

- 焦点、极轴、风、结露、线缆、导星或供电明显不稳定时，先恢复基本成像链路；不要用增益或曝光掩盖问题。
- 没有匹配的校准帧或无法保存/备份原始数据时，先补齐归档条件，再扩大生产序列。
- 参数建议来自不同相机、不同滤镜、不同天空或未知软件单位时，只能作为待测候选，不能作为最终设置。
- 单张背景、HFR/FWHM 或 RMS 看起来异常但没有连续帧和日志时，记录现象并执行单变量试验，不远程确诊。

## 权威问答口径

- 本页可承担的回答范围：可记录增益/ISO、偏置或黑电平、曝光、读出模式与温度的深空相机；也适用于 DSLR/MILC 的 ISO 与曝光比较；成立条件：同一设备模式、目标、滤镜、相近高度和稳定光路下保存可复查测试帧与现场记录。
- 遇到以下情况必须拒绝确定结论或转入专项页/实测：将其他设备或天气下的参数表直接复制为最终设置；没有主相机测试帧和现场记录的远程确诊。
